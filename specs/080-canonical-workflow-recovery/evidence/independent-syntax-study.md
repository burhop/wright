> **Historical scope (2026-09-01):** this study evaluated the exhaustive recovery DSL now preserved as `fixtures/mounting-bracket.workflow.internal-ir.wflow`. It does not evaluate the current engineer-facing `mounting-bracket.workflow.wflow`, which is a contextual authoring projection using `workflow`, `item`, `input`, and `task` sections. See `syntax-evaluation.md` for the current projection evidence. The measurements below remain unchanged historical evidence.

**Evaluator**: independent read-only Codex agent
**Method**: in-memory harness; evaluator imported without invoking its evidence-writing path
**Canonical semantic SHA-256**: `dadc3d6a2e274973a9fd16f6eecd95ac1c3dac2f6ebd38c5b83b4e6a2705acb6`

This study directly edited generated source at stable-ID anchors. It did not mutate an in-memory IR and then reformat, so it independently probes the user/agent editing boundary. It is still a fixture-scale agent study, not a representative mechanical-engineer study or model benchmark.

All three original parser/schema boundaries rejected only 4/8 invalid controls. JSON and YAML offered one line/column parse error, three object paths without source spans, and no diagnostics for accepted invalids. DSL offered two exact-line parser errors, two whole-section-correlatable schema errors, and no diagnostic for accepted invalids. Its map covered 44 semantic sections but not significant field spans/columns.

Other measured limits:

- JSON comments fail parsing.
- YAML comments parse but disappear after canonical formatting.
- DSL preserved one leading standalone comment; arbitrary formatting/comment placement was not tested.
- Repository-owned DSL implementation is 229 LOC across scalar/section/format/parse paths; comparing it with “1 LOC JSON / 2 LOC YAML” is not an end-to-end parser cost comparison.
- There was no representative engineer cohort, independent multi-model generation sample, CST policy, field-level source mapping, or migration corpus.

## Strict recovery-kernel closure

The recovery conformance kernel and `tests/recovery/test_workflow_conformance.py` close the disclosed fixture controls without retroactively changing the original measurement:

- strict JSON and YAML duplicate-key rejection;
- non-finite-number rejection;
- DSL unknown-field and duplicate-field rejection;
- global stable-ID uniqueness;
- cross-entity reference, ownership, direction, and port-type validation;
- structured `WFR-*` diagnostics with explanation and correction;
- last-valid preservation for invalid text, graph commands, and stale AI proposals.

The focused suite passes 23/23 tests, and every treatment now rejects 8/8 syntax controls. The additional graph controls cover duplicate endpoints, feedback ownership/order, non-feedback cycles, cardinality, exact phase/port reciprocity, binding-map sources, component interface ports, and exact semantic/layout history authority. This proves the recovery kernel behavior for the golden fixture; it does not prove a permanent syntax.

## Conclusion

Strict JSON remains a reasonable internal interchange candidate after the strict-loader and semantic-validator boundary. The DSL remains useful only as a disposable Code-mode treatment because it exposes the clearest section-to-block/port correspondence. YAML remains viable if a concrete-syntax-tree, comment, formatting, and source-map policy is justified.

No permanent user-facing syntax is selected. `DEC-P0-002` remains open pending representative engineer review, independent model samples, field-level diagnostics, and migration/unknown-version evidence.
