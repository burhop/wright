# Quickstart: Human-Repeatable Acceptance

## Preconditions

- Use an isolated local data root and exact candidate commit.
- Enable both server and web composer flags.
- Keep the immutable Process Definition feature enabled for compatibility comparison.
- Use no external credential, MCP server, model, or network service.

## Journey 1: Empty to four blocks

1. Open **Workflow Composer** and create a working draft.
2. Add Capture requirements, Define product, Review product definition, and Release product definition.
3. Arrange them in named phases.
4. Add compatible typed ports and connect them in order.
5. Add the approval gate, its proceed target, labeled revision feedback, and intended artifacts.
6. Compare Diagram and Text and record the full semantic-ID set from each.

**Pass**: Four blocks and all declared concepts are distinct, readable, and identity sets match exactly. No execution-oriented action exists.

## Journey 2: Invalid edit and recovery

1. Attempt to connect two outputs or incompatible value types.
2. Read the diagnostic and affected identities.
3. Correct the named cause and validate again.

**Pass**: The invalid intent does not replace the last valid draft or prior saved revision; the correction clears the diagnostic.

## Journey 3: Save, close, reopen

1. Save the valid composition and record revision and semantic/layout digests.
2. Close the draft, reopen it, and compare all identities, relationships, declared concepts, and positions.
3. Attempt one stale-revision save from a separate test client.

**Pass**: Reopened semantics are exactly equal, all four positions are preserved, and the stale save leaves the current revision unchanged.

## Journey 4: Accessibility and fallback

1. Repeat primary actions by keyboard with visible focus.
2. Inspect at 390 CSS pixels and 200% zoom.
3. Inject renderer unavailability and use the text/properties fallback.

**Pass**: Complete inspection, diagnostics, and recovery remain reachable; no document-level horizontal overflow or serious/critical accessibility finding occurs.

## Journey 5: Removal and non-interference

1. Record the immutable Process Definition API bytes, ETag, page identity set, and selected existing journey results.
2. Disable both composer flags and restart.
3. Repeat the Process Definition and selected existing journeys.

**Pass**: Composer navigation/API authority is absent; released bytes and ETag are unchanged; existing journeys pass; the inert draft sidecar requires no released-data migration or cleanup.

## Evidence

For implementation Checkpoints C, D, and E, create or continue a Playwright UI walkthrough containing `progress.md`, `status.json`, raw and annotated screenshots, browser diagnostics, trace, and a clickable report. Update the progress dashboard at least every second increment.
