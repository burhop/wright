# Confined engineering working copies

Implemented 2026-09-12 for native engineering hosts that save in place and lack SaveAs. This is a generic canonical MCP operation, not a PCB/template executor. It does not parse or execute copied files and does not dispatch native tools.

`wright-workspace-files__copy_file` accepts exactly `sourcePath` and `destinationPath`, both literal workspace-relative strings (maximum 512 characters). Bind it as a direct `mcp-tool`, with no model task or connected/dynamic argument substitutions. The destination parent must already exist. Its current schema/provenance digest is `3d1eb786a6da2edcd2d42e858432377ffcecafc5450c20d50bac6ba7c18cc791`.

Authority requires the authenticated immutable automatic integration grant, exact current canonical step, server/tool/schema, workspace and runtime session. The source is either an exact enrolled input with its pinned SHA256, or an earlier current-run result whose producer declared that file in `expected_files`. The canonical engine supplies verified engineering results before each step, including authenticated continuation restoration. Tool response JSON, arbitrary files already on disk, public approval context and another run's results cannot supply this authority. Source, input, grant and argument identities are checked again after the durable authorization audit, immediately before a private, expiring, single-use permit is issued.

The destination must be a new file below this attempt's enrolled output root, distinct from the saved receipt path using filesystem path comparison (including Windows case aliases). Existing targets are never overwritten. Workspace paths reject traversal, absolute paths, ADS, links and reparse points. Copies stream at most 256 MiB. Source identity is checked before/after streaming; actual copied bytes are separately hashed against the authorized source. Windows ancestor/source handles prevent rename/delete and source writes; the temporary read/write handle denies other writes/deletion through publication. POSIX uses a pinned destination directory descriptor, no-follow opens and identity checks. Atomic hard-link publication never replaces a target. Errors clean temporary data and compensate only the exact inode published by this call.

The structured receipt contains source/destination paths, actual byte counts and SHA256, input or producing-run/result lineage, source definition digest, copy step, request ID and integration policy digest. The provider returns no artifact ID/resource link and never publishes a final artifact automatically. For a mutable working copy, omit its destination from the copy node's `expected_files`; seal the bytes only in the later native-edit step. For an explicitly final copy, declare its destination in `expected_files`, allowing ordinary canonical runtime verification to publish it after the copy. The provider's `mutable_working_copy: true`/`published_artifact: false` describes the provider boundary before any explicit runtime final-output verification.

The existing inspection operation now recognizes `.kicad_pcb`, `.kicad_pro`, and `.kicad_sch` as metadata-only formats. Existing write and inspect input schemas/provenance pins remain unchanged:

- Write: `66c045c726240dd539b71339450e63e3056b4cf2c8d30954d407c027a17b0b12`.
- Inspect: `b0c9ce7a52c766833056df2615e0a29e4d11641d639b91174da51c8ac9cc330a`.

Tests exercise actual binary copying, GatewayService/provider dispatch, full canonical two-copy production lineage, mutable/final artifact distinctions, exact audit count, manual/revoked/forged authority, source/input/definition/schema/argument drift, single-use/session/expiry, size bounds, Windows case aliases, source/parent/target races and actual temporary-byte tampering. Symlink tests skip where the host denies symlink creation. File-presence/identity tests do not claim engineering content correctness.

Deployment requires a controlled Wright API restart and fresh discovery/enrollment for new copy nodes. No Hermes or selected engineering-host restart is required by this change. Existing enrolled definitions/grants and live native workflows are untouched by implementation/testing.
