# Current Milestone Dashboard Contract

Extend current-work status while preserving immutable historical readiness and old bundle compatibility. Milestone ID `NATIVE-01`, title `Native engineering process: create to verified output`.

Stable acceptance/task IDs, scope revision/history, branch/PR/baseline, blockers/owners/actions and next work are required. Tasks have independent implementation/verification/integration states; counts/denominators derive from actual rows. Never average them into product completion or grant verification/deployment credit from a checked task alone.

Evidence includes kind/result/time, tested commit/tree or scoped source identity, covered tasks/acceptance, author/verifier, exact links and applicable result counts. Missing/failed/skipped/untested/stale evidence stays visible. Separate report recency from tested-code coverage: a later evidence commit is not changed product code, but changed covered code invalidates its credit. File presence cannot establish passed quality or authority.

Acceptance IDs: AC01 truthful dashboard; AC02 native semantics; AC03 accessible author/save/reopen; AC04 shared UI/headless execution; AC05 artifacts/provenance; AC06 failure/cancel/recovery; AC07 exact real local MCP; AC08 three examples/independent assertions; AC09 offline/distribution/compatibility; AC10 independent technical/human review and verified dev deployment.

Default page: delivered capabilities → milestone/remaining criteria → task stages/current work/blockers → quality/candidate identity → examples → expandable historical readiness/governance. Benchmark remains 0/100 until qualified separately. Keep product/benchmark/commercial/release distinct. Refresh failure preserves previous valid display with a visible stale/error state.

State that the native language is the authority for AI/canvas/runtime. Display native milestone delivery and remaining Rivet migration/retirement separately; an implemented native path must never imply legacy conversion or retirement is complete. Autonomous AI authoring remains a future capability, separate from the shared programmatic contract delivered here.

Test false counts, absent evidence, invalid references, changed candidate, old bundle fallback and synchronized installed contracts. Actual browser verification covers narrow/keyboard/evidence/freshness. Publish meaningful checkpoints, not a bookkeeping commit for every edit.
