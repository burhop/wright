# Complete the experimental Wright desktop workspace journey

The desktop prototype could open workflows but left users dependent on another
Wright UI for common workspace, connection, file and recovery operations. This
change puts those operations beside the desktop conversation while retaining
the shared canvas, accepted source and existing runtime/gateway authority.

The native panel adds scoped workspace settings and durable draft recovery,
catalog/custom-command setup and lifecycle/tool controls, saved setup recovery,
uploads, exact historical results and navigation. Normal workspace MCP tasks use
the existing bounded decision loop and current workspace permissions. Two shared
fixes allow finite JSON numbers in local protocol validation and avoid demanding
a model callback for a deterministic tool-only process. Signed catalog hashing,
frozen model routing, reviews and uncertain-effect enforcement remain intact.

Validation includes an actual desktop-reasoned Playwright task, distinct input,
review/cancel/reconnect/restart/denial cases, and an existing two-operation Blender
workflow with preserved requirements and independent exact-output checks. The
frozen combined candidate separately passes gateway/image/review and MCP/resource
checks; the exact ARM64 Docker image passes its existing cold-start smoke. Required
formatting corrections are mechanical and separately committed.

**Draft / not ready to merge:** the normal current merge gate failed because
the upstream vulnerability database was expired. Broad post-scan regressions are
independent diagnostics, not a passing gate. Windows-native acceptance, real
cross-host OAuth completion, current-head CI and exact merged-dev deployment
remain outstanding. No follow-on push or merge has occurred.

Retain the experimental label. Generated process-UI authoring, automatic desktop
wakeups/reasoning restart, and unreported model/app identity/cost are unavailable.
Full named engineering campaigns and physical acceptance are outside this goal.
