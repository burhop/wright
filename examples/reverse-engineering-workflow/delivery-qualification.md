# Reusable example delivery — 1 November 2026

An engineer supplies a request and existing images or documents, reuses the
available evidence, and identifies the remaining essential gaps before modeling.
Open the supplied-material source in the normal workspace Workflows editor. The
research-first builder can also bind explicitly installed search/fetch tools.
Independent inspection builders and measurement helpers support later stages;
they are separate segments, not a complete automatic photo-to-CAD process.

## Qualification and ownership

The Windows pilot originals and all historical runs remain preserved. This
delivery uses current `dev` after PR #176, which already supplies exact image-frame
and structured-container validation. No duplicate runtime, model route, UI,
approval mechanism or vendor protocol is added. The existing source compiler,
instruction assets, result identities, validator and durable runtime retain their
authority. Missing required capabilities hold the affected work. The normal
common view remains the fallback; no new browser acceptance is claimed.

The ordinary `tests/reverse_engineering/` suite contains 25 source/evidence
regressions. They validate source compilation, declared clarification, bounded
attachments, instruction tamper detection, frame identity and camera-hypothesis
spread. They need only Wright's existing gate environment and are collected by
the normal repository pytest target.

The optional geometry suites contain native STEP round-trip, analytic ray,
section, two-view correspondence, projected-envelope, visibility and mesh
visualization controls. These use generated fixtures, not Roadster geometry.
They establish the tested numerical and topology behavior, not real-photo camera
calibration, dimensional accuracy, finished CAD, printability or human acceptance.
Actual model requests were not made for this delivery. The Astra/high provenance
files describe earlier authoring/qualification only; they do not select a route
for a new run. Each new run must resolve and freeze its own configured route.

Historical different-domain evidence includes the unchanged Robot Tracking
measurement/validator controls and pocket-defect correction artifacts. Those
receipts remain private pilot evidence with the scopes documented in the dated
notes. This source delivery does not replay them or claim a fresh MCP campaign.

## Repeat the checks

Run the ordinary contracts from the repository root:

```powershell
uv run --extra runtime --extra engineering-models python -m pytest -q tests/reverse_engineering
```

For optional geometry tests, use an isolated environment with Wright's runtime
and the dependencies listed in `geometry-test-requirements.txt`. Set both
`NATIVE_FACE_AUDIT_TEMP` and `STEP_RAY_AUDIT_TEMP` to an existing absolute local
directory dedicated to fresh qualification evidence, then run:

```powershell
python -m pytest -q examples/reverse-engineering-research examples/reverse-engineering-workflow
```

These tests retain some fixtures intentionally. The chosen directory must have
space for their evidence. Do not point it at an existing run or model directory.
No hosted CAD, provider dispatch, account change or physical operation is needed.
Full dev-push/merge gates and current-head CI remain separate delivery checks.

## Historical provenance and current source

The original authoring manifests and instruction bodies remain unchanged.
Python helpers were formatted and three unused imports removed for repository
lint. Three lightweight test modules moved into `tests/reverse_engineering/` for
normal collection, with the preparation bundle locator adjusted accordingly.
`delivery-source-manifest.json` records original byte hashes and delivered Git
blob hashes and locations, so Windows newline conversion is explicit. Historical
`source_files` hashes identify the original authored files,
not the formatted delivery. Do not rewrite an old receipt to describe a new run.

The old rejected research draft and unsupported proposal schema remain labeled
historical. Use `research-first/research-first-v2.workflow.wflow` for the current
supplied-material example. Automatic optional zero-call research, connected CAD
authoring/export/correction, exact-output revalidation across restart, real image
calibration, native contact/mesh-intersection capability qualification and human
engineering acceptance remain outside this delivery's fresh proof. The method
inventory includes proposed methods, not a registry of installed integrations.

The latest preserved Roadster checkpoint is B26, an incomplete open shell.
Roadster execution is paused by the user's current instruction. It is not part
of these qualification runs or this reusable-example acceptance.
